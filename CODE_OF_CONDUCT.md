Code of Conduct

Our standard

WaveHelm is an open-source project intended to support constructive technical collaboration.
Participants are expected to communicate professionally, stay focused on the technical subject, and treat other contributors and users with respect.
Examples of acceptable behavior include:

giving clear, specific, and actionable technical feedback;

disagreeing with ideas without attacking the person presenting them;

asking for evidence, reproduction steps, tests, or clarification;

acknowledging mistakes and correcting them;

respecting different levels of experience and different technical approaches;

keeping discussions relevant to the project.

Unacceptable behavior includes:

harassment, threats, intimidation, or personal attacks;

discriminatory or demeaning language;

deliberate disruption of Issues, Discussions, Pull Requests, or reviews;

repeated bad-faith arguments after a maintainer has clarified scope or evidence requirements;

publishing private, identifying, confidential, or security-sensitive information without permission;

spam, unrelated promotion, or abusive use of project communication channels.

Technical disagreement

Technical disagreement is welcome.

Strong criticism of code, architecture, tests, documentation, assumptions, or design decisions is acceptable when it remains specific and evidence-based.

Criticism should target the work, not the person.

When possible, support claims with:

reproduction steps;

failing tests;

logs;

documentation;

benchmark results;

references to platform or API behavior.

Security reports

Suspected security vulnerabilities must not be disclosed through public Issues, Discussions, Pull Requests, commits, or social channels.

Use GitHub Private Vulnerability Reporting:

https://github.com/1981-teck/WaveHelm/security/advisories/new

Maintainer responsibilities

The maintainer may edit, hide, lock, or remove content that violates this Code of Conduct and may restrict participation when necessary to protect the project and its community.

Moderation decisions should be based on behavior and project relevance, not on technical disagreement alone.

Scope

This Code of Conduct applies to participation in WaveHelm's public project spaces, including:

Issues;

Discussions;

Pull Requests;

code review;

repository-hosted documentation;

other official WaveHelm collaboration channels.

Reporting conduct problems

For ordinary project disagreements, use the relevant Issue, Discussion, or Pull Request.
For serious conduct concerns that should not be handled publicly, contact the maintainer through an appropriate private channel.
Security vulnerabilities must use the private security reporting process described above.
